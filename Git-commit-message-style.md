# Git Commit Message Style

My preferred commit message format. This applies to **all** repositories I
work in (`geoschem/gcpy`, `geoschem/geos-chem`, `geoschem/GCHP`, and others),
not just one.

## Template

```
<Imperative subject line, no trailing period>

<Short prose: what was wrong and why the fix is what it is.
Explain the reasoning, not a restatement of the diff.>

path/to/first_file.py
- Bullet describing a change
- Another bullet

path/to/second_file.py
- Bullet describing a change

CHANGELOG.md
- Updated accordingly

Signed-off-by: Bob Yantosca <yantosca@seas.harvard.edu>
Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
```

## Rules

**Subject line.** Imperative mood ("Fix ...", "Add ...", "Now use ...",
"Silence ..."), no trailing period. Keep it under ~72 characters so it does
not wrap in `git log --oneline`.

**Default to brief.** A short paragraph of prose plus the per-file section is
usually enough. Do not write several narrative paragraphs restating reasoning
that already lives in the code comments and the CHANGELOG. Length should scale
to the size and subtlety of the change — a genuinely tricky fix earns a longer
body, a one-line format change does not.

**Body prose explains *why*.** The per-file bullets already say *what*. Use
the prose for the failure mode, the constraint that forced the approach, or
the reason an obvious alternative was rejected. Concrete numbers help
("a relative spread of 7.5e-6, which the 1e-5 tolerance swallowed").

**Per-file section.** Bare file path on its own line, then `- ` bullets
beneath it. This is the part reviewers scan, so keep the paths in a sensible
order (the substantive change first, tests and docs after). Omit the section
entirely for a single-file change whose subject line already says everything.

**CHANGELOG.md.** When the repo keeps one, add an entry and note it in the
message as `CHANGELOG.md` / `- Updated accordingly`.

**Sign-offs.** End with my `Signed-off-by:` line, plus a `Co-Authored-By:`
line naming the model when Claude did the work. Both go last, after the
per-file section. The `geoschem` repos use `Signed-off-by:` consistently; this
documentation repo often carries `Co-Authored-By:` alone, so match whatever the
surrounding history does.

## Worked examples

A small, self-explanatory change — prose omitted entirely:

```
Ignore benign user warnings in file_regrid.py

gcpy/file_regrid.py
- Added code to filter out RuntimeWarning messages generated by
  xesmf

CHANGELOG.md
- Updated accordingly

Signed-off-by: Bob Yantosca <yantosca@seas.harvard.edu>
```

A subtle numerical fix — prose carries the reasoning, and no per-file section
is needed because the subject and prose already localize it:

```
Make the difference and ratio rows agree about when Ref and Dev differ

Difference panels are symmetric about zero, so testing their full span
measured twice the largest |Dev - Ref| and applied half of
NOISE_REL_TOL, while ref_equals_dev applied all of it.  A 7.5e-6
relative difference fell in the gap, so the difference row plotted a
real offset while the ratio row beside it reported "Ref and Dev equal
throughout domain".  diff_is_negligible now states the criterion once,
and NOISE_REL_TOL becomes 5e-6 so that only the ratio row moves.

Signed-off-by: Bob Yantosca <yantosca@seas.harvard.edu>
Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
```

A larger change touching several files does get the full treatment — see
`a5ea5d0` in `geoschem/gcpy` ("Say why a ratio panel has nothing to show"),
which runs to roughly fifty lines with per-file bullets for four files. That
is the upper end, not the target.

## Anti-patterns

- Restating the diff line by line in prose.
- A body that repeats the CHANGELOG entry verbatim.
- Multi-paragraph narratives on a two-line change.
- Trailing period on the subject line.
- Omitting the `Signed-off-by:` line.
